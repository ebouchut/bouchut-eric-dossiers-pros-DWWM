Introduction

Le besoin

  • Contexte: Apprendre à programmer suppose un parcours structuré :
    • du contenu organisé,
    • une progression lisible,
    • un espace où un formateur publie et fait évoluer ses cours.
  • Problème : offrir un environnement multi-rôles simple, sûr et accessible.
  • Solution :

    learn-dev est une plateforme Web où des formateurs publient des cours composés de leçons en Markdown, et où des étudiants s’inscrivent et les suivent.

Vue d’ensemble de learn-dev

Rôles

  • étudiant (STUDENT)
  • formateur (INSTRUCTOR)
  • administrateur (ADMIN)

Authentification et Autorisations

  • Authentification obligatoire
  • Autorisations (RBAC) :

    Une fois authentifié, un utilisateur n’a accès qu’aux fonctionnalités que lui accorde son rôle.

Etudiant

Rôle STUDENT

  • création de son compte :
    • rôle par défaut,
    • aucune restriction,
  • consultation du catalogue des cours,
  • inscription à des cours,
  • lecture des leçons.

Formateur

Rôle INSTRUCTOR :

  • création de contenu (cours et leçons),
  • cycle de vie de publication des cours et leçons,
  • gestion des inscriptions.

Administrateur

Rôle ADMIN:

  • gestion des comptes,
  • modération des contenus.

Base de données — MLD

Modèle Logique de Données - Indépendant de la base de données - Structure relationnelle partielle - tables - tables de jointure - modélisent la cardinalité N,N - clé étrangères (Foreign Keys) - précédées par # - modélisent les cardinalités 1,1 et 1,N ::right::

Base de données — MPD

Modèle Physique de Données - Syntaxe spécifique au moteur de base de données relationelle choisi (SGBDR) - PostgreSQL (ADR-07), - Clés primaires (ADR-03) : - UUID pour la table users - anti-IDOR (top-10 des vulnérabilités OWASP) - BIGINT pour les autres tables - Clé primaire composite pour les 2 tables de jonction - Diagramme MPD à suivre (ou équivalent Markdown plus digérable ;-)

  • Erreurs HTTP explicites :

    • Pas de 401 : Authentification échouée
    • 403 : Authorisation insuffisante
    • 404 : On ne le présente plus
    • 409 : conflit dans les paramètres de la requête
    • 500 : erreur du serveur <!– (~1 min)

  • Voici ls 2 features que je vais détailler ensuite.

  • Si authentification échoue Spring Security (FormLogin) :
    • ne renvoie PAS 401
    • ne donne PAS la cause (login indexistant ou mot de passe incorrect)
    • redirige (302) sur la page de login –>

Feature 1 — Inscription d’un utilisateur(CP4, CP7)

- Formulaire **validé** (Bean Validation), **erreurs accessibles**. - **Unicité** username/e-mail ; motif **Post-Redirect-Get**. 
public User register(RegisterForm form) {
    if (users.existsByUsername(form.username())) {
        throw new DuplicateUsernameException();
    }
    if (users.existsByEmail(form.email())) {
        throw new DuplicateEmailException();
    }
    // hachage BCrypt, jamais de mot de passe en clair
    user.setPassword(encoder.encode(form.password()));
    return users.saveAndFlush(user);
}

# Accès aux données <small>(CP6)</small>

- **Spring Data JPA** : *repositories* = interfaces, requêtes **dérivées** et
  **paramétrées** (anti-injection SQL) ; `@Transactional`.
- **NoSQL** : MongoDB **provisionné** en vue d'un stockage de contenu (non encore branché).

```java
public interface UserRepository extends JpaRepository<User, UUID> {

    @EntityGraph(attributePaths = "roles")   // l'utilisateur ET ses rôles en 1 requête
    Optional<User> findByUsername(String username);

    boolean existsByUsername(String username);
    boolean existsByEmail(String email);
}

Sécurité

- **BCrypt**, **CSRF** activé, **anti-XSS** (jsoup). - **Anti-IDOR** (UUID), **anti-énumération**, **verrouillage de compte**, **rate-limiting**. - Jetons **hachés SHA-256**, **journal d'audit**, matrice d'autorisations **testée**. - Référence **OWASP Top 10** ; veille **Semgrep**.

(HttpOnly, SameSite=Lax) end ```
